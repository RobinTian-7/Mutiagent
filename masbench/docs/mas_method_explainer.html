1. 五分钟版本:这件事到底在干什么

想象一支被关在不同房间的解题小队。每个人手里只有一部分题目材料,谁也看不到全貌;他们不能开会,只能按一张事先画好的"传纸条路线图"通信:第 1 轮谁传给谁、第 2 轮谁传给谁、最后由谁交卷。

这张路线图(通信拓扑)的好坏,直接决定这队人能不能做对题。链式传递适合"按顺序拼接"的题;星型汇聚适合"投票汇总"的题;画错了图,再聪明的队员也会把关键信息在中途弄丢。

本仓库做的事:让一个"架构师 AI"通过反复实验,自己学会给不同类型的题画对路线图——并且用一套相当苛刻的法庭程序证明:它画的图,稳定优于(a)不学习的冷启动画图、(b)直接照搬历史最优经验、(c)人类预设的四种固定路线图里在训练集上表现最好的那一种。

关键设定
队员(worker agents)的提示词全程冻结,从不训练、从不改动。所有的"学习"只发生在架构师一侧:它积累的是设计规则(什么结构在什么任务上灵/不灵的带证据的卡片),不是队员的解题能力。这样一来,成绩的提升只能来自"组织方式变好了"这一条因果路径——这正是我们要证明的论点。

整个项目的另一半是防自欺:判分脚本被冻结(谁也不许改)、实验方案先注册后执行、每一笔 API 开销记账、失败必须根因分析后才能再试。下文 §7 会展开。

2. 任务与赛场:Silo-Bench 和 JSSP

2.1 主赛场:Silo-Bench(信息孤岛协作)

每个任务把一份数据切成 N 片(shard),发给 N 个 agent。题目类型包括:统计全局词频、找跨片最长回文、按片顺序拼接序列、输出组合结构的答案等。Agent 之间只能按给定的拓扑在给定轮次发消息,最后指定一人交卷,按精确匹配率(Exact-Match)判分。

难点在于:不同题型需要的信息流形状完全不同——

  • 顺序敏感型(如跨片回文/拼接):必须让相邻片的边界信息互通,且不能有损压缩;
  • 聚合型(如词频/最值):需要树状或星状汇聚,中途可以摘要;
  • 组合答案型(答案是个数组/结构):末端还得有"组装"步骤,否则各自报数凑不成完整答案。

2.2 佐证赛场:JSSP 作业车间调度(M-APPLE-OS / REALM-Bench,arXiv:2502.18836)

每个 agent 持有一个作业(job)的工序表(机器、耗时),机器互斥,团队要协商出一张全局调度表,最小化总完工时间(makespan)。这是与 Silo 完全不同的任务族——用来回答"这套学习方法是否只对 Silo 有效"。接入是纯增量的:确定性的调度验证器逐条检查工序顺序与机器互斥,答案有效才按质量(已知上界 ÷ 实际 makespan)计分。

3. 核心论点:通信拓扑是一种可以自我改进的"设计技能"

用一句话陈述论文级主张:

我们把 agent 间的通信拓扑重新表述为一种自我改进的设计技能:一个 LLM 架构师在"带证据条件的设计规则记忆"约束下,为每个任务设计时序有向无环图(temporal DAG:第 k 轮谁→谁、最终谁持有答案),可执行的动作词汇为 Preserve(原样重放被信任的结构)/ Modify(保留结构、改写每步角色指令)/ Avoid(规避被证伪的结构);工人侧完全冻结,学习只发生在架构师侧。

三个动作不是修辞,分别对应代码里三条可审计的路径:

动作触发条件(简化)执行时发生什么
Preserve该结构在当前任务的精确槽位上有直接成功证据存档的 DAG 原样重放(连步骤指令一起)
Modify结构可信,但证据来自邻近槽位(如答案形状不同)结构保留;架构师按当前任务重写每一步的接收方指令后部署
Avoid结构有"明显劣于同袍"的成败记录进入负面卡片,生成新图时作为反例约束

4. 系统四层:执行、设计、记忆、学习

4.1 执行层(exp-graph:ProtocolRunner)

给定一张时序 DAG 和任务分片,逐轮执行:每条边是一次"发件人摘要 → 收件人合并"的 LLM 调用(温度 0),最后由 selected_primary 指定的 agent 产出最终答案。若步骤带指令(M9),会以"本轮你的步骤角色:…"的形式注入收件人的合并提示词。执行层不学习,是公共的、确定性的舞台。

4.2 设计层(graph generation:架构师)

架构师为每个任务生成多个候选 DAG:一部分由 LLM 现场设计(受 max_steps / max_messages / fan-in 预算约束、自动修复显式错误),一部分由技能库中被信任的结构播种(skill-seeded replay)。候选去重(结构等价哈希,保留带指令的代表)、按 motif 先验与不确定性下界打分、再按"重放优先 + 粘性在位者"规则选出冠军(见 §5)。

4.3 记忆层(SkillBank 技能卡 + motif 统计)

记忆的最小单元是技能卡(SkillCard),核心字段:

skill_id            身份(含结构等价哈希做的家族归并,防"同结构different名字"碎片化)
organization_policy
  ├ protocol_spec   可执行的 DAG 存档(含每步指令)——"技能"是可运行的工件,不是一句口号
  ├ transfer_evidence  信任账本:每个 任务桶#槽位 的 {n, em_sum, cases[]}
  └ deploy_action   部署期标记 preserve / modify
trigger             适用条件(任务族、agent 数、条件键)
expected_tradeoff   均值损失、样本数、evidence_case_count(去重案例数)等检索统计

另有 motif 统计:把每张图分解成结构特征(扇入档位、是否有汇聚点、归约深度、消息总量……),按任务桶记账各特征与损失的关联,作为生成新图时的先验。motif 键带任务桶前缀,一个范式上挣的结构学分不会泄漏到另一个范式。

4.4 学习层(masbench:进化轮)

每一轮进化在训练案例上做四件事(全部不触碰测试案例):

① 证据收集:跑一组命名拓扑组合(M3/M15 组合证据:聚合系 + 链式 + 网状,训练与验证种子)+ 热温探索的自生成结构,得到带任务分类标签的逐行成绩。
↓
② 蒸馏:ResultAnalyst minister 把行打成技能卡补丁(冠军卡、avoid 卡);误触发的 avoid 被过滤(需要真实的平均损失差距,而非二值行上的比例规则误火)。
↓
③ 门控:把"接受补丁后的库"放到保留验证集上试做(M5 种子×3 + 允许一次失手的 ε 容差;M2 棘轮:与在位库比,不是与空库比)。变差的更新整批拒绝——坏经验进不了库。
↓
④ 信任记账:把本轮所有行折进每张卡的 transfer_evidence(按结构身份归并重复),盖 deploy_action 标记,更新 motif 学分。库跨轮累积(initial_skills 续传)。

5. 方法的心脏:一次部署决策的完整链路

测试时面对一个没见过的任务,系统按以下链路决定"用哪张图、以什么动作":

第 1 步:任务分类(M7 / M12 / M16)

用运行中的同一个 LLM 回答五个与基准无关的问题(温度 0,按题面文本哈希缓存):顺序敏感吗?答案在单个 agent 处还是全局?统计族是什么?需要无损传递吗?答案是标量还是组合结构?由此得出任务桶(of/os/os-seg)和槽位键:

槽位 = 任务桶 # (lossless|lossy)-(scalar|composite)
例:跨片回文长度 → os#lossless-scalar;输出每片配对数组 → os#lossless-composite

为什么是这两个机制位:它们分别对应被实测分离过的两种失败模式——"摘要会不会丢掉答案所需的信息"(dev-5 的 vote/count 双峰)与"答案要不要末端组装"(dev-9 的标量保护 vs 组合塌陷)。正则启发式只作为离线 fake 模式的后备,真实运行一律走 LLM 分类——这是"可泛化、不许针对 Silo 写死"的操作员条款的直接落实。

第 2 步:查信任账本(M1 / M6→M8 / M16b / M19b)

对库里每张卡问:"你在这个槽位上可信吗?"规则按证据精细度分层,且方向不对称:

  1. 直接证据优先:该槽位有 ≥2 行记录且平均 EM ≥ 0.5 → 信任(动作 Preserve);记录在案的失败 → 不信任。一行幸运不构成信任。
  2. 形状外推(M16b):槽位没量过,但同损失性、另一形状的兄弟槽位通过了 → 可部署,动作自动转 Modify(结构可信,指令要按新答案形状重写)。损失性维度永不外推(有损证据不能授权无损任务)——那是能力边界,不是适配边界。
  3. M19b 全局多样性门:正向外推还要求这张卡在全部证据里至少出现过 2 个不同案例(防止"单案例配方"骑着外推横扫一切,dev-11 事故);负向(测得失败)在任何多样性下都拦截——失败比成功更可信。
  4. 广度外推(M8):完全没量过的维度,需要 ≥2 个子槽位通过且零失败才许外推。"没有反例"≠"一致好评",证据窄就只挣窄信任。

第 3 步:检索排序(M4 / M19a)

可信卡片按"悲观损失"排序:

排序损失 = 平均损失 + 0.5/√(行数) + 0.25/去重案例数

第二项是经典 LCB(样本少 → 先持怀疑);第三项是 dev-11 买来的教训:同一案例的多个种子是相关样本,不是独立证据。一张"1 个案例上 2 行满分"的新卡(罚 0.25)排不过"7 个案例上身经百战"的老将(罚 0.036)。

第 4 步:候选竞争与冠军选择(round-10 稳定性三件套)

  • replay_first:存在被信任的重放候选时,新鲜生成的候选不参与冠军竞选(它们只在探索期挣证据);
  • 粘性在位者:motif 先验要把在位冠军挤下台,优势必须超过 0.1 的边际——近似平手不换人(dev-6 的 r3 崩盘就是平手乱洗牌);
  • 带指令优先的去重:结构等价的候选合并时,保留带指令的那份(裸结构孪生卡曾把指令版顶掉)。

第 5 步:执行动作(M14 / M9)

Preserve → 原样重放(指令一起);Modify → 架构师读任务简报,为每一步写一条 ≤200 字符的接收方指令(解析失败重试一次),注入合并提示词。实测这一步是地板破除器:II-17/II-18 在逐字重放下 72 战 0 胜,加上按任务改写的指令后变成可赢(screen-B +22.2pp)。

第 6 步:分层兜底与弃权(round-12 / M1)

槽位可信的重放  →  桶级可信的强通才(动作 Modify)  →  与冷启动完全一致的路径

没有任何可信卡时,系统弃权:跑出来的图与空库冷启动逐字节相同——"不知道时不装懂",这让弃权在 stable 判官下是中性的(不输给基线),也是 do-no-harm 条款的实现。

6. 配方搜索与"验证什么就部署什么"

6.1 M10:训练期验证式配方搜索(Reflexion / STaR 思路)

有的训练案例上,所有现成结构都不及格——一锤子买卖式的证据收集永远造不出锚点。于是:让 LLM 针对该案例提出带每步指令的完整程序(配方),立刻在 2 个种子上执行验证;失败给程序性反馈再试(≤4 次);通过防泄漏扫描(配方文本不得含分片字面量)后,验证通过的配方才入库。它的账本行就是它的验证行——"先验证,后信任"。

6.2 dev-11 事故与 M19c:验证与部署必须是同一工件

事故复盘(2026-06-12 当天)
一张在 II-13 上验证 2/2 通过的配方卡(5 步、每步带回文专用指令、40 条消息),部署时被预算修复器(max_messages=32)砍掉第 5 步(全局答案步)并丢光全部指令——实际跑的是 4 步裸结构,与验证过的东西不是同一份工件;它还凭"2 行满分"赢下检索,部署到所有测试案例上,整条曲线归零(4.2/0.0/4.2 vs 基线 8.3)。

修复(M19c):修复器重建步骤时保留指令字段;skill_* 重放候选按存档工件的实际尺寸放宽预算——预算约束的是"现场生成",不是"重放已验证执行过的工件";新鲜候选仍受预算约束。加上 §5 的 M19a/M19b 双护栏后,同一格子翻成 45.8*/62.5*/45.8* 全程压制。

7. 防自欺机器:两个冻结判官与预注册协议

方法再漂亮,没有可信的判分都是空话。本仓库的验证层有四道互锁:

7.1 判官一:stable(verify_evolve_stable.py,冻结)

问"进化有没有真实、持续的提升":同管线冷启动(空库、无 motif 先验)在保留网格(测试案例 × 评测种子)上测出基线;然后 R 轮累积进化,每轮结束都在同一网格上配对评测。

PASS ⇔ 最后 stable_rounds(=2)轮,每轮都满足:
       均值 ≥ 基线 + 5pp  且  (赢的对数 − 输的对数) ≥ 2

一轮走运过不了;冲高回落过不了。

7.2 判官二:4-arm(verify_beats_baselines.py,冻结)

问"打不打得过最好的替代方案":完整进化后,最终库在同一网格上与三条基线臂逐对(同案例同种子)比:

臂是什么控制什么
select同一库,纯检索重放最优技能架构师的设计是否比"照抄最好经验"多赚了东西
graphgen冷启动现场画图(空库)零经验下限
fixed{tree, mesh_star, one_peer_exp, chain} 中训练集上最强者最好的人类预设拓扑——操作员点名要"无条件干掉"的对象
PASS ⇔ 对【每一条】臂:均值差 ≥ 5pp 且 独胜数 − 独负数 ≥ 2

7.3 程序正义

  • 判分脚本冻结:红线明令不许改 verify_evolve*;修复永远进管线,不进法庭。
  • 预注册:每个开发轮先在 selfevolve_phase3_preregistration.md 登记案例划分、种子、代码版本和要回答的问题,再开跑;方法变更(M1–M19)逐条记录动机与出处。
  • 终局验收(confirmatory):现场 RNG 抽取划分与种子并记录、空缓存起跑、两模式 × 两判官四格全 exit 0;最多 3 次机会,失败必须先有根因修复,不许换种子重抽。
  • 账本:每一笔真实 API 开销记入 COST_LEDGER.json(当前 $52.89 / $100 上限),作废的运行也入账并标注 INVALID/DIAGNOSTIC。
  • 机制纯度审计:每个胜局都要追溯到"库内技能 → 架构师 → 部署的组织(+指令)"的因果链;解释不通的涨分按过拟合处理、拒绝入账。

7.4 一个重要的测量发现:供应商时间漂移

同一确定性策略、同一批种子,在相隔 28 分钟的两次测量里可以从 20.8% 掉到 0.0%(p≈4e-4)。这意味着:(a)统计功效的杠杆是更多案例而不是更多种子(同案例种子间高度相关);(b)判读对比时必须配对同窗口;(c)±4pp 量级的臂间差应读作噪声宽度。这条发现直接塑造了上面的判据与 M19a 的"案例数"项。

10. 诚实的边界声明

  1. 规模边界:全部结论在 n=5 agents、gpt-4o-mini、温度 0 条件下取得。n=10 侦察显示该模型在此基准上能力地板更深(双臂全零),组织优化救不了执行力不存在的地方——"组织记忆不能创造执行者没有的能力"是本项目实测的硬边界(dev-4:0 胜/72 局)。
  2. 案例池边界:Silo 在 n=5 下有动态范围的 II 级案例只有 4 个,全部在开发期被触碰过。因此终局验收的"未动过"只能在划分+种子+空缓存层面成立(SHAPE v3,操作员知情批准),它证明的是"未见过的组合上可重复",不是"全新任务上的泛化"——后者由 JSSP 佐证补位。
  3. II-17 仍是地板:该案例在最近几轮对所有臂都是 0%(包括人类预设拓扑),系统在它上面的正确行为是不伤害(同 0),而非创造奇迹。
  4. 漂移噪声:±4pp 量级的单次臂间差不构成结论;这正是判据要求"连续多轮 + 赢负边际"且加固轮要换种子复扫的原因。

11. 词汇表

拓扑 / 时序 DAG
"第 k 轮谁发消息给谁、最终谁交卷"的有向图;本项目的被学习对象。
冷启动(coldgen)
同一套管线,但技能库为空、无 motif 先验——"没有记忆的自己"。
gen / refine 两种模式
gen(graph_generate):架构师现场设计 DAG,技能只作为播种与先验;refine(select_then_refine):优先检索重放库内最优工件再精修。两者都要过全部判官。
技能卡(SkillCard)
带可执行 DAG 存档、信任账本、触发条件的记忆单元;"经验"的落地形态。
信任账本(transfer_evidence)
每张卡按"任务桶#槽位"记 {行数 n、EM 总和、去重案例表};一切部署授权的依据。
槽位(slot)
任务桶 #(lossless|lossy)-(scalar|composite):证据被允许声明效力的最小单位。
门控(gate)
每轮更新入库前在保留验证集上的预演;变差整批拒绝;M2 棘轮 = 与在位库比而非空库比。
motif
图的结构特征(扇入、深度、汇点……)与成绩的关联统计,按任务桶隔离,作生成先验。
配方(recipe)
M10 在训练期为困难案例搜索并当场验证的"结构+每步指令"完整程序。
弃权(abstain)
无可信技能时部署与冷启动逐字节相同的路径;do-no-harm 的实现。
EM(Exact-Match)
最终答案与标准答案精确一致的比率;Silo 的主判分。
pp(百分点)
percentage point;"+12.5pp"即均值高 12.5 个百分点。
confirmatory
预注册的终局验收:现场抽签、空缓存、四格全过、≤3 次机会。
